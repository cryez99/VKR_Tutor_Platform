## Краткое описание системы
Разрабатываемая система — это веб-платформа, объединяющая репетитора и учеников. Она решает проблему разрозненности инструментов (мессенджеры, почта, бумажные тетради), предоставляя единое окно для коммуникации, обмена ссылками на видеозвонки, выдачи и сдачи домашних заданий, мониторинга прогресса учеников. Главное нововедение — интеграция ИИ для автоматической проверки решений учеников и помощи ученикам в понимании каких-либо тем, что экономит время преподавателя.

## 1. Перечень заинтересованных лиц (стейкхолдеров)

В системе выделено 4 ключевых стейкхолдера, включая внешнего (API нейросети).

| ID | Стейкхолдер | Роль | Интересы / цели | Влияние |
|----|-------------|------|-----------------|---------|
| SH-01 | Репетитор | Основной пользователь, администратор своих учеников | Автоматизация проверки ДЗ, экономия времени, единое окно для общения и ведения учеников | Высокое |
| SH-02 | Ученик | Пользователь, выполняющий задания | Удобный интерфейс для сдачи ДЗ, быстрая обратная связь от ИИ/репетитора, доступ к ссылкам на уроки | Среднее |
| SH-03 | Внешний AI-сервис (OpenRouter API или BotHub API/ локальная LLM) | Внешний сервис, проверяющий решения | Получение корректного формата данных (текст, фото решения) и возврат оценки/фидбека | Высокое |
| SH-04 | Платежный шлюз (ЮKassa/CloudPayments) | Внешний сервис (Возможно) | Проведение оплат за использование репетитором сервиса | Низкое |

## 2. Перечень функциональных требований

Сформулировано 10 требований. Приоритеты расставлены по MoSCoW.

| ID | Требование | Стейкхолдер | Приоритет (MoSCoW) | Обоснование |
|----|------------|-------------|---------------------|-------------|
| FR-01 | Система должна обеспечивать авторизацию пользователей с разделением ролей (Репетитор, Ученик) | SH-01, SH-02 | Must | Без разделения ролей невозможно разграничить доступ к функциям и данным. |
| FR-02 | Репетитор должен иметь возможность создавать учетную запись ученика и отправлять приглашение на почту | SH-01 | Must | Репетитор сам формирует свою базу учеников. |
| FR-03 | Пользователи (репетитор и ученик) должны иметь возможность обмениваться текстовыми сообщениями в реальном времени | SH-01, SH-02 | Must | Закрывает проблему фрагментации общения в мессенджерах. |
| FR-04 | Репетитор должен иметь возможность прикреплять ссылку на видеовстречу (Zoom, Google Meet) к занятию | SH-01 | Must | Ученик должен видеть ссылку в одном месте, а не искать ее в переписке. |
| FR-05 | Репетитор должен иметь возможность создавать задание с текстом, дедлайном и прикрепленными файлами | SH-01 | Must | Базовый функционал выдачи ДЗ. |
| FR-06 | Ученик должен иметь возможность отправлять ответ на задание в виде текста или фотографии | SH-02 | Must | Ученику нужно сдавать работу так, как ему удобно (особенно по математике). |
| FR-07 | Система должна автоматически передавать сданное ДЗ в AI-модуль и возвращать результат проверки (оценку и комментарий) ученику не более чем за 2 минуты | SH-01, SH-02, SH-03 | Must | Ключевая фича проекта — автоматизация проверки. |
| FR-08 | Репетитор должен иметь возможность вручную скорректировать оценку, выставленную ИИ | SH-01 | Should | ИИ может ошибаться, нужен человеческий контроль. |
| FR-09 | Система должна отображать статистику прогресса ученика (график успеваемости за месяц) | SH-01, SH-02 | Should | Мотивация для ученика и аналитика для репетитора. |
| FR-10 | Интеграция с платежным шлюзом для автоматической оплаты занятий | SH-01, SH-04 | Won't | Не реализуется в текущей итерации (MVP), требует сложной интеграции с юридической и финансовой стороны. |

## 3. Диаграмма вариантов использования

**Связь с требованиями:** ID соответствующего FR указан в названии Use Case.

```mermaid
usecase-beta
  actor Tutor("Репетитор")
  actor Student("Ученик")
  actor AI("Внешний AI-сервис")

  systemBoundary "VKR_Tutor Platform" 
    UC01("UC-01 FR-01 Авторизация")
    UC02("UC-02 FR-02 Добавление ученика")
    UC03("UC-03 FR-03 Обмен сообщениями")
    UC04("UC-04 FR-04 Отправка ссылки на урок")
    UC05("UC-05 FR-05 Создание ДЗ")

    UC07("UC-07 FR-07 Проверка ДЗ")

  Tutor --> UC01
  Student --> UC01
  Tutor --> UC02
  Tutor --> UC03
  Student --> UC03

  Tutor --> UC05

  UC08 ..> : include UC07
  UC07 --> AI
```

## 4. Перечень нефункциональных требований

Выбраны 4 наиболее значимых для данного проекта NFR. Остальные (например, локализация на другие языки) отброшены как неактуальные для MVP.

| ID | Категория | Требование | Метрика / критерий приёмки | Почему выбрано |
|----|-----------|------------|----------------------------|----------------|
| NFR-01 | Performance | Время отклика интерфейса чата при отправке сообщений | ≤ 200 мс для 95-го перцентиля | Это мессенджер, задержки раздражают пользователей и делают UX неприятным при использовании. |
| NFR-02 | Security | Защита персональных данных учеников и их работ | Пароли хешируются (bcrypt), данные передаются по TLS 1.3, соответствие 152-ФЗ | Работа с детьми требует строгого соблюдения законодательства о персональных данных. |
| NFR-03 | Reliability | Доступность сервиса для сдачи ДЗ в пиковые утренние и вечерние часы | Uptime ≥ 99.5% в период с 10:00 до 13:00 и с 19:00 до 23:00 | Ученики делают домашку вечером, простой системы приведет к срыву дедлайнов. |
| NFR-04 | Scalability | Обработка очереди запросов к AI при массовой сдаче ДЗ | Выдерживать 100 одновременных запросов к AI без таймаутов | В воскресенье вечером все ученики сдают ДЗ одновременно — нужно кэширование/очередь. |

## 5. Перечень сделанных предположений (повышенная сложность)

Сделаны предположения, влияющие на архитектуру и объем работ.

| ID | Предположение | Влияние на требования |
|----|---------------|-----------------------|
| A-01 | Система разворачивается на российском хостинге, интерфейс на русском языке | Влияет на NFR-02 (152-ФЗ), исключает использование зарубежных облаков (Google Cloud) для хранения персональных данных. |
| A-02 | В качестве AI используется внешнее API (OpenRouter или, скорее всего, BotHub), так как развертывание своей LLM слишком дорого | Влияет на архитектуру (нужен модуль интеграции), добавляет риск недоступности внешнего сервиса в определенное время. |
| A-03 | Система рассчитана на 1 репетитора | Упрощает БД и авторизацию, не нужно делать сложную систему для школ, где учителей много. |
